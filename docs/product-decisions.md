# Lexiro 產品與資料邏輯決策紀錄

> 這份文件記錄使用者在 grill-me 討論中已確認的產品方向。
> 後續實作前，應先以這份文件為準；尚未確認的內容不得自行假設。

## 狀態

- 討論狀態：進行中
- 最後更新：2026-08-01
- 目的：統一資料模型、題目流程、匯入匯出、字典與 Cloud Sync，避免同一功能存在多套邏輯。

## 已確認的決定

### 1. 不做獨立的「單字庫」功能

- 使用者不需要另外管理一個獨立的單字庫。
- 每個被保存的單字都必須屬於至少一個單字集。
- 程式內部可以共用同一份單字資料，避免同一個單字重複保存，但這只是內部資料整理，不是額外的使用者功能。
- 單字集畫面要顯示：
  - 目前單字集收錄的字義
  - 同一單字在其他單字集收錄的字義

### 2. 同一個英文單字只保存一份

- 相同英文單字不應在不同單字集各自複製完整資料。
- 單字集只記錄自己收錄了哪個單字、哪些字義。
- 不同單字集可以收錄同一個英文單字的不同字義。

### 3. Sense 的重複判斷

- 同一個英文單字底下，只有「詞性相同」且「中文意思相同」才算同一個 sense。
- 詞性或中文意思其中一個不同，就建立新的 sense。
- 同一個 sense 可以保存多個例句。
- 從不同來源匯入相同 sense 時，例句要合併到同一個 sense 底下，不要建立重複 sense。
- 同一個 sense 的例句是共用的，不依單字集分開保存。
- 所有收錄這個 sense 的單字集，都顯示這個 sense 的完整例句列表。
- 詞性比對忽略大小寫和前後空白。
- 中文意思比對只移除前後空白，不做其他自動改寫。
- 不做 AI 模糊判斷，也不做「請使用者確認是否合併」的功能。
- `跑步`、`奔跑`、`跑步。` 視為不同中文意思。

### 4. 單字畫面的資料呈現

單字畫面應呈現類似以下結構：

```text
單字：run

本單字集收錄：
- 動詞｜跑步
  - 多個例句
- 動詞｜經營
  - 多個例句

其他單字集收錄：
- 名詞｜一連串活動
  - 多個例句
```

### 5. Dictionary API 查詢與加入流程

Dictionary API 查詢結果預設只顯示，不自動寫入自己的資料。

按下「加入我的單字集」後，要開啟 Dialog，流程為：

1. 選擇要加入的單字集。
2. 顯示 API 抓回的詞性與例句。
3. 使用者勾選要保存的詞性。
4. 使用者勾選要保存的例句。
5. API 抓回的詞性與例句可以在 Dialog 裡修改。
6. 中文意思由使用者手動輸入。
7. 確認後才寫入單字集和共用單字資料。

### 6. 不保存英文字義

- Dictionary API 的英文定義只在 API 結果卡片中顯示。
- 不把 API 英文定義保存成自己的單字資料。
- 不要求使用者輸入英文字義。
- 新資料模型不保存 `definition` / `definitionEn` 欄位；實作時直接移除，不保留相容性欄位。

### 7. 手動新增單字的畫面

手動新增時採用「一個單字一個區塊」的方式：

```text
單字：run

字義 1
詞性：動詞
中文意思：跑步
例句：
- 例句一
- 例句二
[新增例句]

字義 2
詞性：動詞
中文意思：經營
例句：
- 例句一
[新增例句]

[新增另一個字義]
```

- 同一個單字只輸入一次。
- 一個單字可以新增多個字義。
- 一個字義可以新增多個例句。
- 手動新增流程要有例句欄位；目前的手動新增表單沒有例句，必須修改。

### 8. 不保留標籤與收藏

- 不需要標籤功能。
- 不需要收藏功能。
- 新資料模型、畫面、匯入匯出與 Cloud Sync 都不再使用這兩個欄位。
- 新資料模型不包含 `tags` 或 `favorite` 欄位，也不為它們保留任何相容處理。

### 9. 單字必須有單字集歸屬

- 如果單字仍然被其他單字集使用，刪除某個單字集時只移除該單字集的關聯。
- 如果單字已經不屬於任何單字集，刪除這個單字，以及底下的所有字義和例句。
- 不保留使用者看不到、也沒有單字集歸屬的孤兒單字資料。

### 10. 發音與音檔

- 發音標記只在 Dictionary API 查詢結果中顯示，不保存到自己的單字資料。
- 不保存音檔網址或音檔資料。
- 已保存的單字使用瀏覽器語音朗讀。
- 不讓不同單字集重複保存發音或音檔。

### 11. 同義詞與反義詞

- 同義詞只在 Dictionary API 卡片中顯示。
- 反義詞只在 Dictionary API 卡片中顯示。
- 不保存到自己的單字資料。
- 不進入 Cloud Sync 或 ZIP 備份。

### 12. 移除字源與資料來源欄位

- 不保存 `origin`。
- 不保存 `dictionarySource`。
- Dictionary API 或其他來源資訊只在外部資料卡片中暫時顯示。
- 自己的單字資料只保留單字、詞性、中文意思和多個例句。

### 13. Dictionary API 加入已存在的單字

- 如果單字已經存在，Dialog 要顯示目前已保存的字義，讓使用者選擇。
- 每個從 API 回來的例句，都要讓使用者選擇它對應哪一個既有 sense。
- 使用者可以選擇任一個既有 sense，該例句就加入那個 sense。
- 如果沒有任何既有 sense 適合，使用者選擇「新增 sense」。
- 新 sense 的詞性與中文意思由使用者填寫或修改。
- 儲存時仍使用「詞性＋中文意思」判斷重複，避免建立真正重複的 sense；不另外提供合併確認流程。
- 使用者可以在 Dialog 裡選擇「加入既有 sense」或「新增 sense」。
- 不因為加入另一個單字集而複製整個單字。

### 14. 填空題只保留四選一

- 填空題固定是「句子挖空後，從四個選項選答案」。
- 不做使用者自行輸入答案的打字填空題。
- 題目生成、作答、判分、結果、每日題目都只維護這一套填空邏輯。

### 15. 一般四選一與四選一填空是兩種獨立題型

- 一般四選一是獨立題型。
- 四選一填空是另一個獨立題型。
- 兩者要有不同的題目類型名稱。
- 兩者分開生成。
- 兩者分開保存。
- 兩者分開提供複習模式入口。
- 兩者分開統計題目數量與作答結果。
- 即使底層都使用四選一選項，也不能在產品邏輯上混成同一種題型。

### 16. 閱讀理解保留為第三種正式題型

- 閱讀理解是一篇文章加上多個子題。
- 它和一般四選一、四選一填空分開。
- 閱讀理解有自己的生成、儲存、複習入口和統計。
- 文章與子題要能正確關聯到相關單字和 sense。

### 17. 移除拼字題

- 不保留拼字題。
- 移除拼字題的複習入口、路由、Session mode、作答、判分和統計邏輯。
- 不留下未完成或沒有 UI 入口的半套拼字功能。

### 18. AI Prompt 以 output 題庫的理想寫法為參考

- 這裡的「Prompt」是交給 AI 的生成指令，不是題目資料裡的 `prompt` 欄位。
- AI 生成指令的語氣、句型、難度和選項風格，先參考 `output/questions` 裡的既有題目。
- 一般四選一參考 `multipleChoice-006` 等 polysemy 題目的語境辨義結構，但真正生成時題目和四個答案都必須是英文。
- 一般四選一的方向是：英文提問、英文例句、四個英文解釋或英文答案選項。
- 四選一填空參考 `multipleChoice-001` 等題目：自然英文句子挖空，四個英文單字選項。
- 閱讀理解參考 `reading-002`、`reading-009` 等完整資料：完整英文文章，搭配英文的主旨、推論、詞義、指涉、作者態度等閱讀問題。
- `cloze-001`、`cloze-025` 等舊拼字或重組句子資料不作為正式題型範本。
- `reading-001` 等空白 prompt 或空 `wordKeys` 的舊資料格式不照抄；只參考內容風格，資料關聯和欄位必須重新設計。

### 19. 題目只分三個難度

- 題目難度只保留三段：簡單、中等、困難。
- 單字集本身不再有難度；難度屬於生成出來的每一道題目。
- AI 生成時要把難度傳進對應的 Prompt，不是所有題目都用同一種難度。
- 難度主要調整三件事：
  - 用詞難度
  - 干擾選項的相似程度
  - 題目或文章的長度
- 一般四選一、四選一填空、閱讀理解都要依照這三段難度生成。
- 目前程式裡的 `VocabSet.difficulty` 是舊的單字集難度，後續要移除，不拿它代替題目難度。

### 20. 每一道題都要綁定指定的 sense

- 題目生成的單位是「單字的某一個 sense」，不是只有單字本身。
- 每道題至少要保存對應的 `wordId` 和 `senseId`。
- 同一個單字有多個 sense 時，可以各自生成不同題目，不能把不同意思混在同一題的來源裡。
- 三種正式題型都要能追溯到相關的單字和 sense，方便出題、複習、統計和日後檢查題目是否考到正確意思。

### 21. 生成和測驗可以分開選擇題目難度

- 進入單字集後，使用者在生成題目時選擇要生成的難度：第一級、第二級、第三級，或全部難度。
- 每道生成的題目都要保存自己的難度欄位，例如 `difficulty: 1 | 2 | 3`。
- 開始測驗時，使用者可以選擇：
  - 隨機難度：從所有難度的題目一起抽題。
  - 第一級：只抽第一級題目。
  - 第二級：只抽第二級題目。
  - 第三級：只抽第三級題目。
- 測驗的難度選擇只影響抽題範圍，不會修改題目原本保存的難度。

### 22. 隨機難度要平均涵蓋三種難度

- 測驗選擇「隨機難度」時，不是把所有題目混成一個池子後直接抽。
- 系統要先在第一級、第二級、第三級之間分配題數，再從各難度裡隨機抽題。
- 目標是讓三種難度在同一次測驗中盡量平均出現。
- 如果某個難度的題目不足，先抽出該難度現有的題目，再把剩餘名額分配給其他難度。
- 只要所有難度合計的題目足夠，最後要盡量考滿使用者選擇的題數。
- 補足後仍要盡量維持三種難度的平均分配。

### 23. 每次測驗都可以選擇題數

- 開始每一次測驗前，使用者都可以選擇本次要考幾題。
- 可選的最大題數要依照本次選擇的題型和難度篩選後的可用題目數量決定。
- 題數選擇和題型、難度選擇放在同一個測驗開始設定流程裡。
- 每次開始測驗仍然要顯示設定畫面，不直接跳過詢問。
- 系統會把上次使用的題數填入預設值；如果使用者不想改，可以直接按開始。
- 目前程式確實已有題數滑桿，但舊邏輯主要用單字集 ID 保存題數；重構時要改成適用於「題型＋難度」的統一測驗設定，不保留互相重疊的多套流程。

### 24. 題數偏好由所有題型共用

- 一般四選一、四選一填空、閱讀理解不各自保存一份題數。
- 三種題型共用同一個「上次選擇的題數」作為下一次的預設值。
- 使用者每次仍然可以修改這個預設值，修改後成為下一次共用的預設值。
- 這個共用值要跨所有單字集，不按單字集拆分。

### 25. 題數預設值是全程式共用的一個值

- 所有單字集、所有題型都使用同一個全域題數預設值。
- 例如使用者在 A 單字集的閱讀理解選了 20 題，下一次進入 B 單字集的填空測驗時，也先預填 20 題。
- 使用者可以在任何一次測驗開始前修改它，修改後成為下一次全程式共用的預設值。
- 目前程式的 `practiceCounts` 是依單字集保存，重構時要改成單一共用設定，避免保留兩套行為。

### 26. 隨機難度不足時的補題

- 隨機難度先依第一級、第二級、第三級盡量平均分配題數。
- 某個難度的題目不足時，先取該難度現有題目。
- 剩餘名額再分配給其他難度，盡量考滿使用者選擇的題數。

### 27. 同一個 sense 在一場測驗先只考一題

- 同一個 sense、同一種題型、同一個難度可以保存多道不同題目。
- 一次測驗開始抽題時，第一輪先讓每個符合條件的 sense 最多出現一題。
- 如果使用者選擇的題數大於符合條件的 sense 數量，再從已經出現過的 sense 裡繼續補題。
- 補題時要優先選擇該 sense 尚未考過的其他題目，不重複顯示同一道題。
- 這個規則和隨機難度的補題規則一起使用：先依難度盡量平均，再在各難度內優先做到每個 sense 一題。

### 28. 再次生成時追加題目，不取代舊題

- 同一個單字集、同一個題型和難度再次生成時，保留原本已保存的題目。
- 新生成且通過驗證的題目追加到原本的題庫裡。
- 如果新題和既有題目完全相同，就跳過，不保存重複題。
- 題目生成不應該因為重新按一次生成，就把使用者原本累積的題目清掉。

### 29. AI 題目生成後要先預覽並且可以編輯

- AI 生成的題目不能直接自動保存。
- 生成完成後要先顯示預覽清單。
- 使用者可以在保存前編輯題幹、例句、選項、答案和其他必要欄位。
- 使用者可以刪除不想要的題目，或取消整批生成結果。
- 只有按下確認保存後，通過檢查的題目才加入本地題庫並進入同步流程。
- 如果預覽內容很多，這個流程應使用適合大量編輯的 Page，而不是把所有內容塞在 Dialog 裡。

### 30. 大型操作使用 Page，不要全部使用 Dialog

- 新增單字集改成完整 Page。
- 編輯單字集改成完整 Page。
- 其他需要同時查看大量資料、編輯多個欄位或操作時間較長的流程，也優先使用 Page。
- Dialog 保留給短流程，例如確認刪除、簡短設定、少量欄位或快速操作。
- Page 和 Dialog 的選擇以操作內容的量和複雜度為準，不讓 Dialog 成為所有功能的預設容器。
- Page 內仍然要拆成可維護的元件，不把大型表單全部堆在單一 Vue 檔案裡。

### 31. Vocabulary 編輯 Page 也要管理題目

- 編輯單一 vocabulary 時，可以編輯這個英文單字底下的 sense、詞性、中文意思和例句。
- 同一個 vocabulary 編輯 Page 也要能管理題目：
  - 手動新增題目
  - 編輯既有題目
  - 刪除題目
- 這個 Page 不負責新增、刪除、改名、搬移或整理單字集。
- 手動管理題目和 AI 生成題目是兩條分開的流程。
- 手動新增或編輯題目不應該呼叫 AI，也不應該觸發重新生成。
- AI 生成仍然遵守「生成後預覽、可以編輯、確認後才保存」的流程。
- 題目管理要能依正式題型、難度和關聯 sense 清楚分辨，不能把三種題型混成一個難以維護的表單。

### 32. Dictionary API 加入流程使用多步驟 Dialog

- Dictionary API 的加入流程不改成 Page，使用多步驟 Dialog。
- Dialog 依序處理不同工作，避免把所有欄位塞在同一個畫面：
  1. 選擇一個或多個目標單字集。
  2. 選擇並編輯 API 回傳的詞性和例句。
  3. 把每個例句分配到既有 sense，或選擇新增 sense。
  4. 新增 sense 時輸入中文意思。
  5. 最後檢查並確認保存。
- 使用者可以在步驟之間上一頁、下一頁或取消。
- 在最後確認前，不寫入單字集、共用單字資料或 Cloud Sync。
- 這個流程雖然使用 Dialog，但必須保留足夠的步驟狀態、錯誤提示和編輯空間。

### 33. Dictionary API 一次可以加入多個單字集

- 使用者可以在第一步勾選多個目標單字集。
- 單字和 sense 仍然只保存一份，不因為勾選多個單字集而複製資料。
- 保存時建立同一個 word／sense 和每個選定單字集之間的關聯。
- 多個單字集是否使用完全相同的 sense 和例句選擇，留待下一題確認。

### 34. 多個單字集套用同一套選擇內容

- 一次勾選多個單字集時，使用者只設定一套 sense 和例句選擇。
- 所有選定的單字集都套用相同的 sense 和例句。
- 不在同一個 Dialog 裡為每個單字集做不同的 sense／例句設定。
- 如果不同單字集需要不同內容，就另外執行一次加入流程。

### 35. 加入已存在的 sense 時只增加例句與單字集關聯

- 如果 A 單字集已經有 `run｜動詞｜跑步`，而 Dictionary API 的內容也被使用者判斷為同一個 sense，就不建立新的 sense。
- 使用者選中的 API 例句會加入原本那個共用 sense。
- A 單字集不會產生重複的 sense 關聯。
- 其他已經收錄這個 sense 的單字集，也會看到新增的例句，因為例句屬於共用 sense。
- 其他尚未收錄這個 sense、但在這次被選中的單字集，會新增這個 sense 的關聯。

### 36. 例句使用簡單的完全重複判斷

- 保存例句前先移除前後空白。
- 英文例句不分大小寫判斷完全重複。
- 文字完全相同的例句只保存一次。
- 不做 AI 模糊比對，也不因為兩句意思相近就自動合併。
- 文字不同的例句，即使意思相近，也可以同時保存。

### 37. 題目由 word／sense 共用，不屬於單一單字集

- 同一個 sense 出現在不同單字集時，共用同一批題目。
- 題目保存時連到 `wordId`／`wordKey` 和 `senseId`，不因為單字集不同而複製題目。
- 題目的第一到第三級難度已經能區分難度，不需要為每個單字集各自建立題目版本。
- 從任何單字集生成或手動新增的題目，都加入共用題目池。
- 編輯或刪除一個共用題目，會影響所有收錄該 sense 的單字集；編輯頁需要清楚顯示這個影響範圍。
- 單字集只決定哪些 word／sense 可以進入該次測驗，不擁有自己的題目副本。

### 38. 沒有任何單字集使用的 sense，不保留相關題目

- 如果 sense 從最後一個單字集移除，就刪除這個 sense 底下的共用題目。
- 如果 sense 仍然被其他單字集使用，移除其中一個單字集時不刪除題目。
- 不保留沒有 word／sense 歸屬的孤兒題目。

### 39. 刪除共用題目前要提醒影響範圍

- 編輯單字集刪除共用題目時，要先顯示目前有多少單字集使用這道題。
- 提醒內容要明確說明刪除後會影響所有相關單字集。
- 使用者確認後才真正刪除題目。
- 這是共用題目的刪除確認，不是 sense 合併確認。

### 40. 編輯共用題目前也要提醒影響範圍

- 編輯共用題目時，要顯示這道題目前被多少個單字集使用。
- 要讓使用者看到會受到影響的單字集。
- 保存修改前要再次確認，避免使用者以為只是在修改目前單字集的副本。

### 41. 不另外標記 AI 題目的手動修改狀態

- AI 生成的題目被使用者修改後，不建立額外的「手動修改」標記。
- 保存後，AI 生成題目和手動新增題目使用同一套題目資料和管理邏輯。
- 不依照來源欄位對題目做不同的覆蓋、複習或同步行為。
- 新資料模型不定義 `source` 欄位，也不依照來源建立第二套題目邏輯。

### 42. 題目管理支援三種題型並先選題型

- 編輯單字集 Page 的手動新增題目支援全部三種正式題型：
  - 一般四選一
  - 四選一填空
  - 閱讀理解
- 題目編輯器頂端先使用 Select 選擇題型。
- 選定題型後，才顯示該題型需要的欄位，避免三種題型的欄位同時堆在畫面上。
- 手動新增、AI 預覽和既有題目編輯都使用相同的題型資料格式與驗證規則。
- 在 AI 預覽、編輯單字集 Page，以及其他題目管理位置，使用者都可以手動編輯或刪除題目。
- 刪除共用題目仍然要遵守共用題目的影響範圍提醒和確認規則。

### 43. Dictionary 頁面不顯示題目

- Dictionary 頁面只負責查詢和呈現單字資料，不負責呈現或管理題目。
- 本地資料區顯示單字的所有 sense，並在每個 sense 下面顯示它被哪些單字集收錄。
- Dictionary API 卡片維持顯示 API 的暫時資料。
- 移除 Dictionary 頁面的題目清單、題目預覽、編輯題目和刪除題目操作。
- 題目管理集中在單字集編輯 Page 和 AI 題目生成流程。

### 44. Vocabulary 編輯頁依目前單字集範圍顯示題目

- 從某個單字集進入 vocabulary 編輯頁時，只顯示連到該單字集所收錄 sense 的題目。
- 同一個英文單字在其他單字集收錄、但目前單字集沒有收錄的 sense，其題目不顯示在目前範圍。
- 題目本身仍然是共用資料；編輯或刪除目前頁面顯示的題目時，仍要顯示會影響哪些其他單字集。

### 58. Vocabulary 編輯介面區分目前與其他單字集的 sense

- 編輯介面以單一 vocabulary／英文單字為單位，不以單一 sense 或整個單字集為單位。
- 介面要清楚分成兩個區域：
  - 目前單字集收錄的 sense
  - 其他單字集收錄、但目前單字集沒有收錄的 sense
- 每個 sense 要顯示它所屬的單字集，讓使用者知道為什麼它出現在目前頁面。
- 這個 vocabulary 編輯介面不提供單字集本身的管理功能。
- 題目和例句仍然依 sense 關聯，但不複製成單字集專屬資料。

### 59. 其他單字集的 sense 預設收起且唯讀

- 目前單字集收錄的 sense 預設展開，可以在 vocabulary 編輯頁編輯。
- 其他單字集收錄的 sense 放在獨立的 Toggle 區塊中。
- 其他單字集區塊預設收起，使用者按下後才展開查看。
- 其他單字集的 sense 在目前頁面唯讀；要編輯時，從收錄它的單字集進入同一個 vocabulary 編輯頁。
- 所有單字集仍然使用同一個 vocabulary 編輯元件，不建立另一套編輯畫面。

### 60. Vocabulary 編輯頁不管理單字集歸屬

- Vocabulary 編輯頁只負責共用的 word、sense、例句和題目。
- 不在這個頁面提供加入或移除單字集的功能。
- 哪些 sense 屬於哪些單字集，要由 Dictionary 加入流程或單字集歸屬管理流程處理。
- 這樣可以把「編輯共用單字內容」和「管理單字集收錄範圍」分成兩種清楚的責任。

### 61. 編輯共用 sense 或例句前提醒影響範圍

- 編輯共用 sense 或例句時，要顯示目前有多少個單字集使用這筆資料。
- 修改或刪除前，要讓使用者看到會受影響的單字集。
- 使用者確認後才保存修改或刪除。

### 62. 刪除 sense 先解除目前單字集關聯

- 在目前單字集刪除 sense 時，預設動作是只從目前單字集 unlink 這個 sense。
- 如果其他單字集仍然使用這個 sense，不刪除共用 sense、例句或相關題目。
- 如果已經沒有任何單字集使用這個 sense，才從共用資料中刪除 sense、底下的例句和相關題目。
- 不留下沒有單字集歸屬的孤兒 sense 或孤兒題目。
- 例句是選填；sense 可以沒有任何例句，不能因為例句為空而阻止保存。

### 63. 例句可以逐句刪除

- 刪除例句時以單一句為單位，不一次刪除整個 sense 的所有例句。
- 刪除其中一句後，其他例句保留。
- 如果刪除最後一句，sense 仍然保留，只是例句列表為空。
- 因為例句屬於共用 sense，刪除這一句會影響所有收錄該 sense 的單字集。
- 刪除前要顯示受影響的單字集並要求確認。

### 64. Sense 和例句都可以逐項編輯或刪除

- Sense 可以單獨編輯或刪除。
- 例句可以單獨編輯或刪除。
- 編輯一個項目不應該被迫打開整個 vocabulary 的大表單。
- 刪除和編輯仍然遵守共用資料的影響範圍提醒，以及 sense 沒有單字集使用時的清理規則。

### 65. 明確操作優先使用 Icon，不使用冗長文字按鈕

- Sense 和例句的編輯使用鉛筆 icon。
- Sense 和例句的刪除使用垃圾桶 icon。
- 其他使用者容易理解的常見操作，也優先使用一致的 icon button，不在畫面上堆疊「編輯」「刪除」等文字。
- 每個 icon 必須提供 hover／focus 的 tooltip 和 `aria-label`，確保使用者知道功能，也維持無障礙操作。
- 危險操作仍要用明確的視覺警示和確認流程，不能只因為使用 icon 就省略安全提醒。
- Icon button、tooltip、危險操作樣式要抽成共用元件，避免每個頁面各自實作一套。

### 66. Icon 與文字按鈕的使用界線

- 小型、日常而且容易理解的操作使用 icon，例如新增例句、編輯、刪除、展開、收起和播放。
- 重要流程操作保留文字，例如下一步、確認儲存、開始測驗和取消，避免使用者找不到或不確定意思。
- 只有 icon 的操作仍然必須提供 hover／focus tooltip 和 `aria-label`。
- 這個規則套用到整個產品，不只套用在 vocabulary 編輯頁。

### 67. 編輯 sense 或例句使用小型 Dialog

- 按下 sense 或例句的編輯 icon 後，開啟只處理該筆資料的小型 Dialog。
- 不採用原地把文字替換成輸入框的編輯方式。
- Dialog 只顯示目前這個 sense 或例句需要的欄位，不打開整個 vocabulary 的大型表單。
- 保存、取消、共用資料影響範圍提醒和確認流程，依照各自的資料規則處理。

### 68. 新增 sense 或例句也使用小型 Dialog

- 按下新增 sense 或新增例句的 `+` icon 後，開啟小型 Dialog。
- 新增 sense 的 Dialog 提供詞性、中文意思和可選例句欄位。
- 新增例句的 Dialog 只處理例句內容。
- 新增和編輯使用同一套可重用的 Dialog 元件與驗證邏輯，避免做出兩套表單。

### 69. 題目依複雜度選擇編輯容器

- 一般四選一和四選一填空，每一題用鉛筆／垃圾桶 icon 操作，編輯時開單題小型 Dialog。
- 閱讀理解包含文章和多個子題，使用較大的編輯 Page，不塞進小型 Dialog。
- AI 題目生成結果使用 Page 預覽整批結果，每一題都可以單獨編輯或刪除。
- 題目編輯與刪除仍然遵守共用資料的影響範圍提醒。

### 70. Vocabulary Page 分開管理字義例句與題目

- 資料邏輯分開，但共用同一個 Vocabulary 編輯 Page，讓使用者從同一個單字脈絡管理相關資料。
- Page 以兩個主要分頁區分：
  - 「字義與例句」：管理詞性、中文意思和例句。
  - 「題目」：管理這個單字底下的題目。
- 從單字集點擊單字，或從 Dictionary 的本地單字進入，都使用同一個 Vocabulary Page 元件。
- 從單字集進入時，題目和 sense 依目前單字集範圍過濾；共用題目不因此複製成單字集專屬資料。
- AI 題目生成是獨立流程，但從「題目」分頁進入，不和字義編輯表單混在一起。
- 主要分頁保留文字；分頁內的編輯、刪除、新增等日常操作使用 icon。

### 71. 題目分頁提供題型與難度篩選

- 題目分頁頂端提供題型 Select：全部、一般四選一、四選一填空、閱讀理解。
- 同時提供難度 Select：全部、第一級、第二級、第三級。
- 預設可以查看全部題目，但使用者可以分開查看閱讀理解或特定難度，避免內容混在一起難以管理。
- 新增或編輯題目時，仍然先選擇題型，再顯示該題型需要的欄位。

### 72. Sense 關聯資訊只在編輯介面顯示

- Vocabulary 編輯頁的題目卡片要顯示題目所綁定的詞性、中文意思、題型、難度和題目簡短預覽。
- 這些 sense 關聯資訊只用於編輯和管理時辨認題目。
- 正式練習時不顯示詞性或中文意思，避免提示答案；練習畫面只呈現該題型本身需要的內容。

### 73. FSRS 熟練度綁定 sense，不綁定單一道題目

- 每個 sense 擁有一套 FSRS 記憶狀態。
- 同一個 sense 的不同題目、題型和難度共用這套熟練度。
- 題型和難度只用來決定考法與抽題條件，不因而建立多套熟練度。
- AI 生成更多題目時，不會因此把同一個 sense 拆成多張獨立的 FSRS 卡片。

### 74. FSRS 只使用 Again 和 Good

- 每次練習結果只使用兩種記憶回饋：`Again` 和 `Good`。
- 答錯時記錄為 `Again`。
- 答對且沒有標記不熟時記錄為 `Good`。
- 不提供 `Hard` 或 `Easy`，避免使用者每題面對過多回饋選項。

### 75. Mark 不熟直接記為 FSRS Again

- 答錯時記錄為 `Again`。
- 答對但使用者按下 mark 表示不熟時，也記錄為 `Again`。
- 答對且沒有 mark 時記錄為 `Good`。
- 「重複練習標記」只使用本次練習被標記的 sense，不另存一套永久 mark 狀態。
- 重複練習後由新的答題結果更新 FSRS；不再標記且答對時，該次結果可記為 `Good`。

### 76. 每日複習先到期，再補未學過的 sense

- 每日複習先安排已到期或逾期的 sense。
- 如果還沒達到每日目標，再補未學過的新 sense。
- 新 sense 最多佔每日目標的三分之一。
- 如果沒有任何到期 sense，才讓新 sense 補滿當天目標。
- 從特定單字集進入複習時，只複習該單字集已到期的 sense。

### 77. 相同 sense 在所有單字集共用一張 FSRS 卡

- 同一個 sense 只有一份 FSRS 記憶狀態。
- 在任何單字集中的複習結果，都更新同一份 sense FSRS 狀態。
- 每日總複習不因為同一個 sense 被多個單字集收錄而重複排入。
- 從特定單字集進入複習時，可以考到該 sense，但不建立另一套單字集專屬熟練度。

### 78. 統計分開呈現 FSRS 學習效果與整體練習活動

- 統計頁分開呈現「記憶複習」和「題目練習」，不把兩者硬合成一個總正確率。
- FSRS 統計負責呈現 sense 的記憶狀態、到期數、Again／Good 和熟練度相關資料。
- 題目練習統計負責呈現題目數、題型、難度和答題表現。
- XP 是跨活動的獎勵指標，所有正式練習模式都可以增加 XP，不等同於 FSRS 熟練度。
- 統計要另外記錄持續性，例如目前連續練習天數、歷史最高連續天數和最近一段時間有練習的天數；不把使用者停留在頁面的分鐘數當成主要指標。

### 79. XP 依完成的練習單位計算

- FSRS 記憶複習完成一個 sense，算一個練習單位。
- 一般四選一和四選一填空答完一題，算一個練習單位。
- 閱讀理解以每個子題計算，文章本身不重複計算。
- 答對和答錯都有基本 XP；答對可以另外獲得小額 bonus，但答錯不會完全沒有 XP。
- 完成整場練習和維持連續練習天數，可以另外獲得 bonus。
- 標記後的重複練習也算 XP，但同一個 sense 同一天第一次完整計算，後續重複練習降低 XP，避免反覆刷同一題取得大量經驗。
- 開啟頁面、編輯單字、匯入資料和 AI 生成不算學習 XP。

### 80. Streak 以連續有練習的日期計算

- 不計算使用者花了幾分鐘，只判斷每天是否完成過正式練習。
- FSRS 記憶複習和三種題目練習共用同一個 streak。
- 統計顯示目前連續練習天數、歷史最高連續天數和最近一段時間的練習日期。
- 目前只有 FSRS 複習會更新 streak 的舊邏輯要移除，不能讓題目練習被漏算。

### 81. 每天完成一個正式練習單位即可維持 streak

- 完成一個 FSRS sense 複習、一般四選一、四選一填空或閱讀子題，就算當天有練習。
- 標記題的重複練習也算正式練習。
- 只打開頁面、查看答案或生成 AI 題目不算。
- 不要求完成每日目標才算 streak；每日目標只負責顯示進度。

### 82. 漏練一天時 streak 歸零但保留最高紀錄

- 如果中間漏掉一天，下一次練習時目前 streak 從 1 天重新開始。
- 歷史最高連續天數永久保留。
- 日期以使用者裝置的當地日期判斷，不以 Cloud Server 的 UTC 日期判斷。
- 第一版不做 streak freeze、補簽或寬限日，避免增加另一套例外規則。

### 83. XP 保留 Level，固定每 100 XP 升一級

- XP 是所有正式練習累積的活動分數。
- 每累積 100 XP 升一級。
- Level 只代表活動成就，不代表 FSRS 熟練度或英文能力。
- 統計顯示目前 Level、總 XP 和距離下一級的 XP。
- 刪除單字或答錯不扣除已取得的 XP，避免歷史統計倒退。

### 84. XP 使用固定的練習與獎勵數值

- 每完成一個普通練習單位給 `10 XP`。
- 答對／`Good` 額外給 `2 XP`；答錯／`Again` 仍給基本的 `10 XP`。
- 同一個 sense 同一天第一次以後的重複練習，每次給 `5 XP`。
- 完成一整場練習額外給 `10 XP`。
- 每天第一次完成正式練習額外給 `5 XP`，一天只給一次。
- 這些 XP 獎勵不改變 FSRS 的計算結果。

### 85. 每日複習同時保留記憶目標與題目目標

- 每日目標分成「記憶複習目標」和「題目練習目標」兩個獨立數值。
- 使用者從每日複習入口進入後，先做 sense 的 FSRS 記憶複習，使用 `Good／Again` 回饋。
- 記憶複習完成後，再進入題目練習階段。
- 兩個目標在首頁和統計頁分開顯示，不把 sense 數和題目數相加。
- 題目階段仍遵守三種題型分開的規則，不能因為從每日入口進入就混成一種題型。

### 86. 每日題目階段自動使用 40／40／20 題型比例

- 每日複習完成 FSRS 記憶複習後，不讓使用者另外選題型。
- 題目階段自動按照以下比例抽題：一般四選一 40%、四選一填空 40%、閱讀理解 20%。
- 三種題型仍然分開生成、分開保存、分開管理；只有每日題目隊列會依比例組合。
- 每日題目目標仍然是獨立於記憶複習目標的數值。

### 87. 每日題目比例使用整數分配並在題型不足時補配

- 題目數不是 5 的倍數時，用整數分配方式讓總數正好等於使用者設定的題數。
- 例如 5 題分配為一般四選一 2 題、填空 2 題、閱讀 1 題；10 題分配為 4、4、2。
- 某一題型題目不足時，將缺額分配給其他仍有題目的題型。
- 三種題型總數都不足時，只使用現有題目，不在每日練習中臨時呼叫 AI 生成。
- 抽題仍遵守同一 sense 第一輪最多一題，以及不重複同一道題的規則。

### 88. 每日題目優先考今天剛複習的 sense

- 每日 FSRS 複習完成後，題目階段先從本次剛複習的 sense 抽題。
- 如果這些 sense 沒有足夠題目，再從所有單字集的全域共用題庫補足。
- 補題仍遵守題型比例、難度規則、同一 sense 第一輪最多一題和不重複同一道題。
- 使用者單獨開始題目練習時，才依指定的單字集或範圍直接抽題。

### 89. 每日題目混合三種難度，練習中顯示題目難度

- 每日自動題目階段平均混合第一級、第二級和第三級難度。
- 某個難度題目不足時，使用其他難度補足，但不修改題目原本的難度。
- 題目測驗進行中顯示本題難度，讓使用者知道目前挑戰程度。
- 練習中不顯示會直接提示答案的 sense 中文意思或其他編輯用關聯資訊。
- 單獨開始題目練習時，仍保留隨機難度或手動指定難度的選項。

### 90. 題目正確率計算每一次作答

- XP 計算每一次完成的練習，重複題依既定規則降低 XP，但不完全排除。
- 題目正確率也計算每一次作答，包括重複練習同一道題的結果。
- 重複作答另外標記為 retry，讓統計能區分首次練習和再次練習，但不從正確率中排除。
- 正確率依題型和難度分開統計，不把三種題型混成一個無法解讀的數字。

### 91. 歷史統計只保存有意義的每日彙總

- 不保存每次作答選了哪個答案，也不保存原始答案內容。
- 每日只保存 FSRS 的 Good／Again 次數。
- 每日只保存題目總數、答對數、答錯數，並按題型和難度保存必要的分組計數。
- 每日可以保存 retry 次數和 XP，供統計頁顯示重複練習與活動量。
- 每日保存是否完成過正式練習，供 streak 和日曆使用。
- 每個 sense 的 FSRS 卡片狀態仍然獨立保存，因為那是排程資料，不是逐題答題歷史。
- 不建立保存每一題完整作答內容的永久答題紀錄。

### 92. 統計以 sense 計算，全域總覽優先

- 統計頁預設顯示全域總覽，同一個 sense 只計算一次。
- 單字集是篩選條件，不因同一 sense 被多個單字集收錄而重複加總。
- 單字集篩選可以查看該集合收錄的 sense、到期狀態和相關活動。
- 全域每日複習活動不複製到每一個單字集，避免同一活動被重複統計。
- 從單字集明確開始的活動可以保留單字集脈絡供篩選，但不改變 sense 共用的 FSRS 狀態。

### 93. 熟練狀態使用 FSRS 狀態，不製造虛假的熟練度百分比

- 統計頁不把熟練度硬算成沒有明確意義的 0～100 百分比。
- Sense 狀態分成四類：未學習、學習中、已排程、待複習。
- 未學習代表還沒有複習紀錄。
- 學習中代表正在 learning 或 relearning。
- 已排程代表已進入正式 review，下一次複習時間尚未到。
- 待複習代表已到期或逾期。
- 可以顯示「已開始學習的 sense／全部 sense」比例，但不把它稱為真正熟練度。

### 94. 移除成就系統

- 移除統計頁和首頁的成就區塊。
- 移除成就解鎖判斷與相關業務邏輯。
- 移除成就資料的本地保存與 Cloud Sync。
- 移除成就相關型別、翻譯和 UI。
- XP、Level 和 streak 保留，但不再另外掛成就系統。

### 95. 這是一個全新部署，不支援舊資料相容

- 實作以全新資料模型和全新部署為前提，不做舊資料 migration。
- 不需要支援舊 localStorage、舊 IndexedDB、舊 Cloud schema 或舊匯出格式。
- 不保留舊欄位、舊型別、舊分支或相容性轉換邏輯。
- 文件中所有「migration」「相容舊資料」「保留 legacy 欄位」的做法都不採用。
- 測試只驗證新資料模型、新流程和新部署，不為已移除的舊格式保留測試。

### 96. IndexedDB 是本地唯一資料庫，Cloud 是登入後的權威來源

- 所有 Lexiro 應用資料使用同一個 IndexedDB 保存，作為離線快取和本地工作區。
- localStorage 不再保存應用資料；最多只保存非資料性的 UI 偏好，或完全移除。
- 沒有網路時，App 仍可從 IndexedDB 開啟並使用上次快取的單字集、sense、題目和學習狀態。
- 登入並連線後，Cloud 資料是權威來源；本地不能在初次 Cloud baseline 載入前直接覆蓋 Cloud。
- Firebase SDK 自己的 IndexedDB cache 只供 SDK 離線使用，不取代 Lexiro 的 IndexedDB 資料庫。
- 離線期間的本地修改要先保存在待同步佇列，恢復連線後依明確的衝突規則處理，不使用單純的本地最後寫入時間覆蓋 Cloud。

### 97. Cloud 優先，非衝突自動合併，衝突直接採用 Cloud

- Cloud 永遠是權威版本，本地不能因為 timestamp 較新就覆蓋 Cloud。
- 離線期間的本地修改先進入待同步佇列。
- 本地和 Cloud 修改不同資料項目時，自動合併。
- 同一筆資料發生衝突時，直接採用 Cloud 版本，不把本地修改寫回 Cloud。
- 不提供本地／Cloud 二選一的衝突 Dialog，也不要求使用者手動確認。
- 同步完成後，本地資料回到合併結果或 Cloud 版本，不保留衝突的本地覆蓋結果。

### 98. 以 record 為單位判斷同步衝突

- 不同 ID 的 sense、例句、題目或關聯資料可以自動合併。
- 同一筆 record 同時被修改，或一邊刪除、一邊修改同一筆 record，視為衝突。
- 同一筆 record 發生衝突時直接採用 Cloud，不做欄位級拼接。
- 同一個單字集關聯重複新增時視為冪等操作，不建立重複關聯。
- 不使用不可預測的「本地改一個欄位、Cloud 改另一個欄位」自動拼接邏輯。

### 99. Guest 與 Cloud 帳號資料完全隔離

- 未登入時使用 guest namespace 保存本地資料。
- 登入後使用 user ID 對應的獨立 namespace，不同帳號不能讀取彼此的本地 cache。
- 登入時先載入 Cloud 資料，不把 guest 資料自動上傳或合併到帳號。
- 登出時清除目前記憶體中的帳號資料，回到 guest 或空白狀態。
- 若未來要使用 guest 資料，必須透過明確的完整備份匯入流程。

### 100. Guest 登入前提醒匯出完整備份

- Guest namespace 內有資料時，使用者開始登入流程前顯示提醒，建議先匯出完整備份。
- 完整備份是整個 Lexiro 使用者資料的 ZIP，不是只匯出目前選取的單字集。
- 登入後仍只載入 Cloud，不因為 guest 有資料就自動覆蓋或合併 Cloud。
- Guest 資料只有在使用者之後明確執行匯入備份時，才進入匯入預覽和保存流程。

### 101. Guest 登入前提醒可以選擇繼續

- Guest 有資料時，登入前顯示完整備份提醒 Dialog。
- 主要操作是匯出完整 ZIP。
- 使用者也可以明確選擇繼續登入，或取消並留在 Guest。
- 沒有匯出不會觸發 Guest 到 Cloud 的自動上傳或合併。

### 102. 完整備份包含非敏感 AI 設定，但排除所有 API key

- 完整 ZIP 包含所有單字、sense、例句、單字集、資料夾、關聯、題目、FSRS 狀態、每日統計、XP、Level、streak 和每日目標。
- 完整 ZIP 包含 AI provider、model、endpoint、batch size 和是否啟用 API 模式，但不包含 Prompt 或 AI API key。
- 不包含 Firebase 登入 token 或登入 session。
- 不包含任何其他 API key。
- AI API key 可以只保存在目前裝置的 IndexedDB，不進 Cloud、不進完整 ZIP，也不進任何跨裝置同步資料。
- 更換裝置後需要重新輸入 AI API key。
- 不包含 Firebase SDK 的離線快取、Dictionary API 暫存 cache 或其他可以重新取得的暫時資料。
- ZIP 內包含 manifest，匯入時只接受新資料模型的完整備份格式，先預覽再保存。

### 103. AI Prompt 固定在程式碼，不作為使用者資料同步

- 產品使用的 AI Prompt 固定在程式碼中，不提供使用者自訂 Prompt 欄位。
- Prompt 不進 IndexedDB、Cloud Sync 或完整備份。
- Prompt 改版跟著程式版本發布，不在使用者資料中維護多套 Prompt。
- Cloud 只同步非敏感 AI 設定：provider、model、endpoint、batch size 和是否啟用 API 模式。
- AI API key 只保存在目前裝置的 IndexedDB，不進 Cloud、不進完整 ZIP，也不進 AI 設定匯出檔。
- AI 設定匯入不能帶入或覆蓋 API key；目前會輸出 API key 的舊匯出邏輯必須移除。

### 104. 離線時可使用已快取的本地功能

- 沒有網路時仍可打開 App，使用 IndexedDB 中已快取的單字集、資料夾、sense、例句和題目。
- 離線時仍可進行 FSRS 複習、三種題目練習、編輯資料、匯出完整 ZIP、查看統計、XP 和 streak。
- Dictionary API 查詢、AI API 生成、登入、登出和 Cloud 初次下載等網路功能離線時暫停。
- 離線期間的新增、編輯和刪除先進入待同步佇列，恢復連線後依 Cloud 優先規則處理。

### 105. 恢復網路後自動以 Cloud baseline 先行同步

- 網路恢復後自動開始同步，不要求使用者手動按開始。
- 同步先取得 Cloud 最新版本，再對照本地 pending queue。
- 不同 record 自動合併；同一 record 衝突時採用 Cloud。
- 只把處理後確定可以上傳的變更寫回 Cloud。
- Cloud 寫入完成後，才更新本地 baseline 和即時監聽狀態。
- 介面顯示同步中、已同步、離線或同步失敗狀態；失敗不阻塞 App。

### 106. 同步失敗保留 pending queue 並自動重試

- Cloud 未確認寫入成功前，不刪除 pending queue。
- 網路錯誤使用逐漸拉長間隔的自動重試，不因一般錯誤丟掉本地變更。
- 介面顯示待同步數量、最後錯誤和重新同步 icon。
- 同步失敗時 App 仍可離線使用並繼續累積本地變更。
- 使用者可隨時匯出完整 ZIP 作為額外保護。
- 只有確認為同一 record 的 Cloud 衝突，才依 Cloud 優先規則放棄該筆本地修改。

### 108. Cloud Sync 的資料範圍

- 跨裝置同步單字、sense、例句、單字集、資料夾、關聯和題目。
- 跨裝置同步每個 sense 的 FSRS 狀態。
- 跨裝置同步 XP、Level、streak、每日統計和每日目標。
- 跨裝置同步非敏感 AI 設定：provider、model、endpoint、batch size 和是否啟用 API 模式。
- AI API key、Dictionary API cache、Firebase SDK cache、進行中的測驗 session 和 UI 偏好只保留在目前裝置。

### 109. 完整 ZIP 匯入採合併，不取代現有 Cloud 資料

- 匯入前顯示預覽，列出新增、已存在和衝突資料。
- 匯入不刪除目前帳號已有的 Cloud 資料。
- 不同 record 自動加入；同一 record 衝突時保留目前 Cloud／帳號資料。
- Sense 依詞性加中文意思判斷重複，例句依完全重複規則合併。
- 使用者明確確認後才寫入，匯入完成再進入 Cloud Sync。

### 110. 匯出分成完整備份與選定單字集分享

- 完整備份 ZIP 用於整個使用者資料備份和換裝置，包含學習狀態與統計。
- 選定單字集匯出只包含選定單字集的單字、sense、例句和題目，用於分享或部分轉移。
- 選定單字集匯出不包含 XP、FSRS、Cloud 帳號資料或 API key。
- 兩種匯出用途和格式清楚分開，不讓分享檔意外覆蓋完整學習資料。

### 111. 選定單字集匯入只新增，不覆蓋現有單字集

- 匯入分享檔時永遠建立新的單字集，不覆蓋現有單字集。
- 名稱重複時自動產生簡單後綴，或讓使用者在預覽階段修改名稱。
- 單字、sense 和例句仍依全域共用資料與既定重複規則合併。
- 題目依題型、難度和內容規則去重。
- 匯入前可以選擇資料夾，確認後才保存。

### 112. 根目錄不能直接放單字集

- 根目錄只能包含資料夾，不能直接包含單字集。
- 每個單字集都必須有一個資料夾關聯。
- 「未分類」如果保留，也必須是根目錄底下的實際資料夾，不是根目錄本身。
- 匯入單字集時必須選擇資料夾，不能選根目錄。
- 刪除資料夾時，不能把單字集移到根目錄；必須先移到另一個資料夾，或在資料夾清空前阻止刪除。

### 113. 刪除資料夾時刪除其中所有單字集

- 刪除資料夾不是搬移單字集，而是刪除該資料夾中的所有單字集。
- 刪除前顯示資料夾、單字集數和單字數，並要求明確確認。
- 刪除單字集只解除其與 sense 的關聯；其他單字集仍使用的 sense、例句和題目保留。
- 沒有任何單字集使用的 sense、例句和相關題目，依孤兒清理規則刪除。
- 這是危險操作，不能用一般快速點擊直接完成。

### 114. 刪除資料夾會刪除整棵子資料夾樹

- 刪除上層資料夾時，連同所有子資料夾和底下全部單字集一起刪除。
- 確認畫面列出將刪除的資料夾、單字集和單字總數。
- 不留下孤立的子資料夾。
- 根目錄不可刪除。

### 115. 資料夾可以改名和移動，ID 保持穩定

- 使用者可以重新命名資料夾。
- 使用者可以把資料夾移到另一個資料夾底下。
- 改名或移動只改名稱和 parent folder 關係，不改單字集、sense、題目或 FSRS。
- 資料夾 ID、單字集 ID 和 sense ID 保持不變，且不顯示給使用者。
- 不允許把資料夾移到自己或自己的子資料夾，避免階層循環。

### 116. 同一每日流程中每個 sense 的 FSRS 只更新一次

- 每個 sense 在同一個每日流程最多更新一次 FSRS。
- 先做 FSRS 記憶複習後，後面的題目不再重複排程同一個 sense。
- 如果後面的題目答對，保留本次 FSRS 結果；如果答錯或按 mark，將本次最終結果視為 `Again`。
- 使用者單獨做題目、沒有先做 FSRS 時，才由題目結果更新一次 FSRS。
- 不因為同一個 sense 在同一天出現多道題目，就連續更新多次 FSRS。

### 117. FSRS 進階參數不開放使用者修改

- 使用者只看到 `Again／Good` 兩種回饋。
- 目標記憶率、學習步驟、難度參數和其他 FSRS 進階設定由程式統一管理。
- 設定頁不提供 FSRS 參數輸入，避免使用者把排程調亂。
- 未來若要調整 FSRS 規則，透過程式版本統一調整，不為每個帳號保存不同的 FSRS 參數。

### 118. FSRS 完成後自動進入每日題目階段

- 如果今天仍有題目目標且題庫有可用題目，FSRS 記憶複習完成後直接進入題目練習。
- 題目階段自動使用 40／40／20 比例，不讓使用者重新選題型。
- 使用者可以主動略過今天的題目階段；這不影響已完成的 FSRS 和 streak。
- 如果題庫沒有可用題目，顯示沒有可練習題目，不啟動空白測驗。

### 119. 所有入口共用同一天的每日進度

- 任何入口完成 FSRS sense 複習，都計入當天的記憶複習目標。
- 任何入口完成題目，都計入當天的題目練習目標。
- 每日入口只補足當天尚未完成的數量，不另外建立第二份每日進度。

### 120. 閱讀理解以子題計算，但題組不可拆開

- 每日題目 40／40／20 比例中的閱讀部分，以閱讀文章底下的子題數計算。
- 抽到一個閱讀題組後，必須把該文章的所有子題做完，不能只抽其中幾題。
- 因為題組不可拆開，實際完成題數可能略高於設定的每日題數。
- XP 和題目正確率仍然按每個閱讀子題計算。

### 121. 閱讀題組內所有內容使用同一個難度

- 生成閱讀題組時先指定第一、二或三級難度。
- 文章和該題組的所有子題都使用同一個難度。
- 測驗中顯示題組難度，不在同一篇文章內混用不同難度。
- 如果要練另一個難度，生成或保存另一個對應難度的閱讀題組。

### 122. 單字集不允許為空

- 建立或保存單字集時，至少要有一個單字。
- 不提供空單字集作為整理佔位。
- 如果刪除單字集最後一個單字，必須阻止保存或引導使用者刪除整個單字集。
- 空資料夾仍可存在，但資料夾不能因此直接包含空單字集。

### 123. 刪除單字集最後一個單字時連同單字集一起刪除

- 如果刪除的是單字集裡最後一個單字，確認訊息要明確說明單字集也會被刪除。
- 使用者確認後，同時刪除最後一個單字和該單字集。
- 使用者取消時，單字和單字集都保留。
- 不保存空單字集。
- 共用 sense、例句和題目仍依其他單字集使用情況決定保留或清理。

### 124. 同一個帳號內單字集名稱全域唯一

- 不論資料夾位置，同一個帳號內不能存在相同名稱的單字集。
- 建立或改名時，遇到重複名稱就阻止保存並提示使用者。
- 匯入遇到同名單字集時，先在預覽中要求改名或自動產生後綴。
- 單字集 ID 是內部真正識別；名稱是使用者看到的唯一標籤。

### 125. 資料夾同一層名稱不能重複

- 同一個父資料夾底下，資料夾名稱不能重複。
- 不同父資料夾底下可以有同名資料夾。
- 建立或改名時只檢查同一層級。
- 根目錄底下也不能有兩個同名資料夾。

### 126. 英文單字以去空白和不分大小寫判斷唯一

- 單字身份判斷會去除前後空白。
- 英文字母大小寫不影響身份，例如 `Run` 和 `run` 是同一個 word。
- 內部使用小寫 normalized key 作為唯一識別。
- 不因大小寫建立兩個不同單字。
- 片語的多餘內部空白也要先整理，避免同一句片語因空格差異產生重複資料。

### 45. AI 生成以 sense 為實際選擇單位

- AI 生成畫面以單字分組，但實際勾選的是 sense。
- 使用者可以只選某個單字底下的某一個 sense，也可以一次選取該單字的所有 sense。
- 生成時只把被選中的 sense 送給 AI，不把未選中的其他 sense 混在同一批要求裡。
- 每道生成題目都必須能回到被選中的 word 和 sense。

### 46. 所有 AI 流程使用程式提供的參照代號

- AI 不可以自行發明 word、sense 或 question 的正式 ID。
- 程式送資料給 AI 前，先為本次要求中的每個 word／sense 建立暫時的 `sourceRef`。
- AI 回傳的每個單字資料、題目或閱讀子題，都必須原樣帶回對應的 `sourceRef`。
- 程式收到回覆後，先驗證 `sourceRef` 是否屬於這次要求，成功後才換回正式的 `wordKey`／`senseId`。
- AI 沒有帶參照、帶未知參照或參照錯誤時，拒絕該筆資料，不用模糊比對或猜測。
- 題目的正式 `questionId` 由程式建立，不由 AI 建立。
- 題目要分開保存穩定 ID 和內容重複用的 fingerprint；編輯題目不應因內容改變而失去原本的正式 ID。
- AI 直接 API、複製 Prompt 後手動貼回、單字匯入、三種題型生成，都必須使用同一套參照和驗證邏輯。
- 錯題解析的 AI 回覆雖然不保存成題目，但 Prompt 仍可帶入題目 ID，避免解析對錯題目。

### 47. AI 整理新單字可以提出多個常見 sense

- 第一次把新單字交給 AI 整理時，一個英文單字可以回傳多個 sense。
- AI 只產生詞性和繁體中文意思，不在這個階段產生例句。
- AI 只應提出常見、實用、一般學習情境會遇到的意思。
- 不要提出冷門、艱深、過度專門或只在特殊情況使用的意思。
- AI 結果進入預覽後，使用者可以修改、刪除或調整 sense，也可以依設定產生可選的例句。
- 每個單字最多產生 3 個 sense。

### 48. 使用者提供的詞性和字義優先於 AI 推測

- AI 整理新單字時，使用者可以為每個輸入單字提供詞性和／或繁體中文意思。
- 這些使用者提供的內容要連同單字和 `sourceRef` 一起放進 AI Prompt。
- 使用者已經提供的詞性或中文意思是主要依據，AI 不可以用自己的推測取代它。
- AI 可以在不超過 3 個 sense 的前提下，補充其他常見、實用的 sense。
- 如果使用者沒有提供詞性或中文意思，AI 才負責補充缺少的內容。
- 初次 AI 單字整理仍然只產生詞性和中文意思，不產生例句。
- 回覆進入預覽後，使用者仍可以修改或刪除 AI 結果。

### 49. 保留自由格式的大文字框輸入

- AI 整理單字時，保留目前的大型自由輸入框，不改成逐列表格。
- 使用者可以只輸入英文單字，也可以在同一個文字框裡自行補充中文意思、詞性或其他提示。
- 不要求使用者遵守固定格式或改變原本的輸入習慣。
- AI Prompt 必須保留並帶入使用者的原始輸入內容，讓 AI 從中辨識使用者提供的詞性和字義。
- 使用者在文字框裡提供的意思仍然優先於 AI 自己的推測。
- 程式內部的 `sourceRef` 和資料關聯處理不能要求使用者額外輸入 ID。

### 50. 自由輸入中的重複單字最後只保存一份

- 使用者在自由文字中多次輸入同一個英文單字時，程式最後只保存一個 word。
- 不同詞性或不同中文意思，建立成同一個 word 底下的不同 sense。
- 相同詞性和相同中文意思，合併成同一個 sense。
- 每次輸入出現的參照要先保留，確保使用者提供的不同意思不會在 AI 整理過程中遺失。
- 這個合併仍使用既定的 sense 重複規則，不靠 AI 模糊判斷。

### 51. 使用者提供的中文意思完全保留

- 使用者在自由輸入中提供的中文意思，預覽和保存時都保留原文。
- AI 不可以因為覺得另一個翻譯更自然，就自動替換使用者的意思。
- 如果要改寫中文意思，由使用者在預覽或編輯畫面手動修改。
- AI 可以補充其他 sense，但不能覆蓋使用者已提供的 sense。

### 52. 詞性使用統一格式

- 詞性不保留使用者或外部資料的任意寫法，所有資料最後都轉成程式的統一格式。
- 詞性統一使用常見英文縮寫，例如 `n.`、`v.`、`adj.`、`adv.`、`pron.`、`prep.`、`conj.`、`interj.`。
- `n.`、`noun`、`NOUN` 等同義寫法要轉成同一個標準值；`v.`、`verb` 也一樣。
- Dictionary API、AI 回覆、手動輸入和匯入資料都要使用同一套詞性正規化函式。
- sense 重複判斷使用正規化後的詞性，不再為不同縮寫建立重複 sense。
- 使用者輸入的中文意思仍然依第 51 題保留原文；詞性則依本題規則統一。
- 正式允許的完整詞性縮寫清單，留待下一題確認。

### 53. 詞性顯示和保存使用縮寫

- 不使用 `noun`、`verb`、`adjective` 這類完整英文作為最後保存格式。
- 使用 `n.`、`v.`、`adj.`、`adv.` 等常見縮寫作為標準格式。
- Dictionary API 或 AI 回傳完整詞性時，先轉成標準縮寫再保存。
- 使用者輸入完整詞性或其他大小寫形式時，也轉成相同的標準縮寫。

### 54. 詞性的正式縮寫清單

正式允許的詞性縮寫為：

- `n.` 名詞
- `v.` 動詞
- `adj.` 形容詞
- `adv.` 副詞
- `pron.` 代名詞
- `prep.` 介系詞
- `conj.` 連接詞
- `interj.` 感嘆詞
- `det.` 限定詞
- `aux.` 助動詞
- `modal v.` 情態動詞
- `phr. v.` 片語動詞
- `phr.` 片語

所有外部詞性都要轉換到這份清單中的其中一項。

### 55. 初次輸入和 AI 整理的例句可以選擇是否加入

- 輸入單字、詞性和中文意思的流程要增加例句欄位。
- 手動輸入時，例句不是必填，使用者可以直接跳過。
- 一個 sense 的例句欄位可以新增多筆，但也可以完全沒有例句。
- AI 整理新單字時，提供「生成例句」勾選項。
- 勾選時，AI 為產生的 sense 一起提出例句；不勾選時，AI 不得生成例句，例句保持空白。
- AI 生成的例句仍然要進入預覽，使用者可以修改、刪除或補充。
- 這個選項只控制初次 AI 整理是否產生 sense 例句，不影響題目生成的題幹或閱讀文章。

### 56. AI 每個 sense 預設只生成一個例句

- 使用者勾選生成例句時，每個 sense 先生成一個例句。
- 生成的例句進入預覽，使用者可以修改或刪除。
- 後續可以手動新增更多例句，或從 Dictionary API 選取例句加入。
- 不因為 AI 一次生成多個 sense，就讓每個 sense 自動產生大量例句。

### 57. 題目難度由生成設定決定並由程式驗證

- 使用者在生成前選擇第一級、第二級或第三級難度。
- 程式把選定難度寫進 AI Prompt。
- AI 必須依照指定難度生成題目。
- AI 回傳後，程式檢查題目的難度是否符合這次生成設定。
- AI 不可以自行把題目改成其他難度。

## 尚待實作設計，不需要使用者逐項確認

產品行為和資料規則已由使用者確認。以下只屬於實作層，直接由實作時依本文件選擇乾淨、唯一的方案：

- IndexedDB 的 object store、索引和交易邊界。
- pending queue 的內部欄位、重試間隔和 Cloud API 寫入批次。
- Cloud Firestore 文件／chunk 的實際拆分方式。
- FSRS 套件的固定參數、日期計算和 migration-free 初始狀態。
- Vue Page、Dialog、共用元件和路由的拆分方式。
- 統計頁的圖表元件、版面細節和響應式排版。
- 測試資料工廠、測試案例分組和 CI 執行順序。

## 程式審核時的基準

- 以新資料模型和新部署為唯一實作基準，不保留目前程式裡未採用的殘留欄位。
- `note`、tags、favorite、definition、phonetic、audio、origin、dictionarySource 等未被確認保存的欄位不進新模型。
- `output/` 可作為 AI Prompt 的內容風格參考；其中的資料檔若要匯入，必須先使用本文件定義的 canonical schema 與欄位，程式不為舊 output 格式保留相容 fallback。
- 沒有接上目前產品流程的舊型別、舊 localStorage、舊 IndexedDB marker 和舊 Cloud schema 都直接移除。
